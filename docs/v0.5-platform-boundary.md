# Rashamon Arc v0.5 Platform Boundary

## Release Notes

Rashamon Arc v0.5.0 is a portability architecture milestone. It does not add
browser product features; it separates browser behavior from Linux-specific
input/display/renderer assumptions while preserving the Linux desktop build.

- Added `linux-desktop` as the default UI feature.
- Added a compile-only `kamelot` feature scaffold for future OS integration.
- Introduced platform traits for display, input, filesystem, network, and timer
  boundaries.
- Extracted `BrowserCoreDriver` so browser state transitions, navigation, tabs,
  overlays, permissions, find, zoom, adblock, and persistence coordination are
  centralized outside the SDL loop.
- Introduced `UiHitTarget` so pixel hit-testing produces semantic UI targets
  before browser behavior is dispatched.
- Introduced `PlatformEvent`, `BrowserKey`, `Modifiers`, and `MouseButton` so
  Linux SDL input maps into a platform-neutral event stream.
- Kept WebKitGTK as the Linux desktop renderer and preserved current smoke-test
  behavior.

Rashamon Arc is split into three practical layers.

## Browser Core

The browser core owns tab state, chrome state, navigation decisions, bookmarks,
history, private-mode rules, permission decisions, and adblock policy. It should
not directly depend on SDL, GTK, WebKitGTK, Linux filesystem layout, or future
Kamelot syscalls.

## Platform Backend

The UI platform backend provides display presentation, input events, filesystem
roots, network identity, and timer/event-loop hooks. The default backend is
`linux-desktop`, which keeps the current SDL2/DRM display path, SDL2 input, and
XDG persistence layout. The `kamelot` backend is a compile-time scaffold for a
future framebuffer, keyboard/mouse, KMFS, and syscall network implementation.

## Renderer Backend

The renderer remains behind `RenderEngine` and `ContentEngine`. WebKitGTK is the
Linux desktop renderer. The no-WebKit fallback remains available for builds that
do not select `linux-desktop`; it is not a Kamelot web engine.

## Current Paths

- Default build: `linux-desktop` UI feature plus WebKitGTK renderer.
- Experimental check: `cargo check -p rashamon-ui --no-default-features --features kamelot`.
- Kamelot path: scaffold only, reports unimplemented platform pieces.

## Next Boundary To Tighten

Move fallback fetch and smoke orchestration out of `main.rs`, then add a small
runtime loop boundary so Linux and Kamelot differ only by event source and frame
presentation.

## Known Limitations

- Kamelot is a compile-only scaffold; it does not run the browser yet.
- WebKitGTK, GTK, and SDL2 remain Linux-desktop-only dependencies.
- Drawing and fallback text rendering still live in `main.rs`.
- Mouse coordinate scaling is still Linux window/framebuffer glue.
- Snapshot-based rendering and suspension wake limitations from v0.4 remain.
