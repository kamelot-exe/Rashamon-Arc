# Rashamon Arc v0.6 Platform Runtime

Rashamon Arc v0.6 introduces a small runtime boundary above the v0.5 platform
event model. The goal is to let Linux desktop and future Kamelot OS code drive
the same browser lifecycle without duplicating browser behavior.

## Release Notes

Rashamon Arc v0.6.0 is a runtime portability milestone. It keeps the Linux
desktop/WebKitGTK browser path intact while moving platform loop ownership
behind a small `PlatformRuntime` interface.

- Added `PlatformRuntime` as the boundary for event polling, framebuffer access,
  frame presentation, tick timing, cursor updates, and future redraw hooks.
- Extracted `LinuxDesktopRuntime` so SDL initialization, SDL input, display
  presentation, framebuffer ownership, coordinate scaling, and native cursor
  changes are no longer owned directly by `main.rs`.
- Added a framebuffer-backed `KamelotRuntime` skeleton with backbuffer,
  front-buffer copy, dimensions, frame counter, event queue scaffold, and
  structural `present_frame`.
- Preserved Linux/WebKitGTK rendering and smoke-test behavior.
- Documented the remaining split between Linux WebKit renderer and future
  Kamelot native/Servo renderer work.

## Browser Core

`BrowserCoreDriver` owns browser state transitions, navigation, tabs, overlays,
permissions, find, downloads, adblock, cursor state, and renderer commands. It
receives normalized `PlatformEvent`s and does not depend on SDL event types.

## PlatformRuntime

`PlatformRuntime` owns platform loop mechanics:

- event polling
- framebuffer access
- frame presentation
- coarse tick timing
- cursor updates
- future redraw/window-size hooks

The browser loop asks the runtime for events, passes them to
`BrowserCoreDriver`, renders into the runtime framebuffer, and asks the runtime
to present the frame.

## LinuxDesktopRuntime

`LinuxDesktopRuntime` is the shipping backend. It owns SDL initialization,
SDL event polling, window-to-framebuffer coordinate scaling, display
presentation, the framebuffer, and native cursor changes. WebKitGTK remains the
Linux renderer behind `RenderEngine`.

## KamelotRuntime

`KamelotRuntime` is a minimal framebuffer-backed runtime skeleton. It allocates
a Rashamon `Framebuffer` as the draw target, owns a front-buffer copy that is
updated by `present_frame`, exposes framebuffer/window dimensions, keeps a
simple frame counter, and has an in-memory event queue for future keyboard and
mouse syscall integration.

The Kamelot path does not depend on SDL2, GTK, WebKitGTK, or Linux window APIs.
Its `tick` method is currently a host-simulation timer, and `should_exit`
returns after one presented frame when there are no queued events. That makes
the path structurally renderable without pretending a real Kamelot OS event loop
exists yet.

Renderer separation remains:

- Linux desktop: WebKitGTK behind `RenderEngine`.
- Kamelot: future Servo/native renderer behind `RenderEngine`; current path is
  framebuffer/runtime architecture only.

## Known Limitations

- Kamelot runtime does not run a real OS syscall loop yet.
- Kamelot event queue is in-memory scaffolding.
- Kamelot `present_frame` copies to an owned front buffer instead of scanning
  out to real hardware.
- Drawing still lives in `main.rs`.
- Fallback text fetch and smoke harness still live in `main.rs`.
- WebKitGTK remains Linux-only.
- Snapshot rendering remains the current display model.
