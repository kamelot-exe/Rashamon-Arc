# Rashamon Arc v0.7 Kamelot Runtime Plumbing

Rashamon Arc v0.7 moves the Kamelot runtime from a framebuffer-only skeleton to
the first OS-facing runtime shape. It still does not implement a real Kamelot
browser, real hardware scanout, syscall input, or Servo integration.

## Runtime Shape

The intended runtime stack is:

- `BrowserCoreDriver`: browser state and behavior.
- `PlatformEvent`: platform-neutral keyboard, mouse, scroll, resize, and quit
  events.
- `KamelotRuntime`: framebuffer ownership, input polling, event queue, timing,
  and present lifecycle.
- Future Kamelot syscalls: keyboard/mouse input and framebuffer scanout.

Linux desktop remains separate through `LinuxDesktopRuntime`, SDL2, and
WebKitGTK.

## Input Flow

`KamelotRuntime` now owns a `KamelotSyscallInputSource`.

The source currently has an empty host-side syscall poller, plus an injection
hook for tests/future runtime code. Its raw event model is intentionally close
to OS input packets:

- keyboard key down
- text input
- relative mouse motion
- absolute mouse position
- mouse button press/release
- scroll wheel delta
- quit

The runtime translates these raw events into `PlatformEvent` values before they
reach `BrowserCoreDriver`. That keeps browser behavior free of SDL and future
Kamelot syscall details.

## Framebuffer Scanout

`KamelotRuntime` now owns a `KamelotScanout` surface instead of a loose
front-buffer copy.

The scanout layer owns:

- framebuffer memory metadata: width, height, stride
- scanout byte memory
- present count
- last-present timing

`present_frame` copies the browser framebuffer into scanout memory and records
the present lifecycle. Real scanout is still a future syscall/hardware hook, but
the ownership boundary now matches the expected OS runtime shape.

## Diagnostics

With `RASHAMON_DEBUG=1`, Kamelot runtime diagnostics report runtime selection,
framebuffer dimensions, first present information, and raw input events.
Normal mode stays quiet.

## Known Limitations

- Kamelot syscall polling is still a host-safe empty hook.
- There is no real keyboard/mouse device integration yet.
- There is no real hardware scanout yet.
- The Kamelot path has no renderer; WebKitGTK remains Linux-only.
- The browser still uses the existing framebuffer drawing path and snapshot
  rendering model.

## Next Step

Wire real Kamelot kernel/userland input packets into `KamelotSyscallInputSource`
and replace `KamelotScanout` memory copy with the real framebuffer scanout
syscall or mapped framebuffer region.
