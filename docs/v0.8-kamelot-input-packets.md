# Rashamon Arc v0.8 Kamelot Input Packets

Rashamon Arc v0.8 adds the first explicit Kamelot-oriented input packet layer.
This is still host-safe runtime plumbing: it does not poll real Kamelot
syscalls yet and does not add framebuffer mmap, scanout hardware, Servo, or new
browser features.

## Packet Model

`KamelotInputPacket` represents the compact messages future Kamelot kernel or
userland input APIs should provide:

- keyboard packet: key, pressed/released state, modifiers
- text packet: UTF-8 text payload
- mouse motion packet: relative dx/dy movement
- mouse position packet: absolute x/y position
- mouse button packet: button and pressed/released state
- scroll packet: vertical delta
- quit packet

Release packets are accepted but currently do not emit browser events because
the platform-neutral browser model only consumes key-down events.

## Event Pipeline

The intended flow is now explicit and deterministic:

```text
Kamelot syscall/input packet
    -> KamelotInputPacket
    -> KamelotInputEvent
    -> PlatformEvent
    -> BrowserCoreDriver
```

`KamelotSyscallInputSource` owns the packet queue, drains it during runtime
polling, converts packets into `KamelotInputEvent`s, and returns those events to
`KamelotRuntime`. The runtime then performs the existing conversion into
platform-neutral `PlatformEvent`s.

## Queue Ownership

`KamelotSyscallInputSource` owns:

- packet queue
- pending converted event queue
- host-safe syscall polling hook
- packet injection hook for future tests/runtime integration

`KamelotRuntime` owns:

- `KamelotSyscallInputSource`
- framebuffer and scanout
- runtime event queue
- mouse position state
- timing and present lifecycle

Linux desktop input remains separate through SDL and `LinuxDesktopRuntime`.

## Diagnostics

With `RASHAMON_DEBUG=1`, the Kamelot path logs:

- packet queued
- packet received
- packet converted
- queue depth
- input poll timing

Normal mode remains quiet.

## Future Integration

The next step is to wire real Kamelot input syscalls into
`KamelotSyscallInputSource::poll_syscalls`, producing `KamelotInputPacket`
values. Browser behavior should not need to change because `BrowserCoreDriver`
continues to receive only `PlatformEvent`s.

## Known Limitations

- Real Kamelot syscall polling is not implemented yet.
- Key release packets are accepted but ignored by the current browser event
  model.
- Text input depends on future Kamelot text/unicode packet support.
- No framebuffer mmap or real scanout is included in this pass.
- No Kamelot renderer exists yet; WebKitGTK remains Linux-only.
